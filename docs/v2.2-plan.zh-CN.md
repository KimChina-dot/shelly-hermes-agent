# Shelly Hermes V2.2 计划 —— 对标主流 Agent 的差距清单

> 背景引用:V2.1 交付后评估结论是"总感觉和目前主流 agent 还是差很远的路"。
> 本文先把差距摊开,再排优先级逐阶段补齐。对标对象:ChatGPT / Claude / Gemini
> 移动端,以及 Manus 类通用 Agent 的核心交互。

## 一、差距分析(按用户可感知程度排序)

| # | 能力 | 主流 Agent | Shelly Hermes 现状 | 差距定性 |
| --- | --- | --- | --- | --- |
| 1 | **图片输入** | 拍照/相册发图,模型直接看图回答 | `AgentMessage.content` 是纯 String,网关只发文本,**完全不能发图** | ★★★ 最大感知差距,架构级缺口 |
| 2 | **文件附件** | 传 PDF/Word/代码文件进对话解析 | 仅 Agent 自己能用 workspace 工具读文件;用户不能主动附文件 | ★★★ |
| 3 | **联网搜索** | Agent 可实时搜索网页再回答 | 无任何 web 工具,模型知识截止训练时间 | ★★★ |
| 4 | **语音输入** | 按住说话→转文字→发送 | 无 | ★★ |
| 5 | **对话分享/导出** | 分享长图/Markdown 导出 | 无 | ★★ |
| 6 | **MCP 连接器** | Claude/ChatGPT 接入外部 MCP 工具 | 1.0 明确"留接口不实现" | ★★ |
| 7 | **规划可视化(todo list)** | Agent 展示执行计划并逐项打勾 | 有思考时间线,无计划清单 | ★(已有时间线可承载) |
| 8 | **Artifacts/画布** | 代码/文档侧栏实时预览 | 有 artifact 概念,无预览面板 | ★ |
| 9 | 记忆系统 | 平台级记忆 | **已具备**(Hermes 账本,V2.1 可配置) | 领先项 |
| 10 | 审批/文件操作安全性 | 主流移动端普遍缺失 | **已具备**(逐 hunk 审批、风险分级) | 领先项 |

结论:**1–3 是硬差距**(用户每天可感知、竞争对手默认就有),先做;4–6 次之;
7–8 锦上添花。9、10 是本 App 相对主流的差异化优势,保持不动。

## 二、阶段规划

### 阶段 29(本期):图片输入(视觉多模态)P0
- `AgentMessage` 增加 `images: List<String>`(data URL),checkpoint 序列化向后兼容。
- `openai_messages.dart`:user 消息带图时编码为 `content: [{type:'text'},{type:'image_url'}]` 分片数组。
- 输入框新增附件按钮(相册选图,`image_picker`,Android 13+ 走 Photo Picker 无需权限);发送前压至最长边 1600px、质量 80。
- 用户气泡显示缩略图;仅视觉模型可用是软约束(发图不拦截,由网关报错并映射成人话)。
- 测试:编码单测、fake model 全链路、widget 测试附件流。

### 阶段 30:文件附件 P0
- 附件面板:文本/代码/CSV 直接注入上下文;PDF 抽文本(pure-dart 方案评估)。
- 大文件截断策略 + token 预算提示。

### 阶段 31:联网搜索工具 P1
- 优先走网关插件:Provider 预设标记支持 `web_search` 的厂商(智谱/OpenRouter `:online`),
  在请求体注入厂商专属参数;不支持的厂商隐藏开关。
- 备选:自实现 `web_search` Agent 工具(DuckDuckGo HTML 解析),作为工具卡呈现。

### 阶段 32:语音输入 P1
- `speech_to_text` 插件,中文识别;按住说话交互,识别结果进输入框可编辑后发送。

### 阶段 33:对话分享导出 P1
- 会话 → Markdown 导出,系统分享面板(system_share channel);工具卡折叠为摘要。

### 阶段 34:MCP 连接器(仅 HTTP/SSE)P2
- MCP client over Streamable HTTP;能力页新增"外部工具"分区;风险等级默认 high 走审批。
