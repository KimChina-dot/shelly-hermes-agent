## 二、PHASE 23:工作区降级与首启引导(P0)

### 2.1 目标
Android 未授权 SAF 目录时,App 不是「所有操作报错」,而是**自动落入演示沙箱**:工具跑在内存文件系统上,审批/插件/记忆全链路可体验;同时给一条明确的升级路径(选择真实目录)。

### 2.2 改动清单(文件 → 具体改法)

1. `flutter/android/app/src/main/kotlin/dev/shelly/shelly_hermes/MainActivity.kt`
   - 新增 method channel 方法 `workspaceStatus`:返回 `{authorized: bool, treeUri: String?}`(读现有 `treeUriPref()`,**不抛异常**,未授权返回 null 字段)。
   - 现有 `readFile/writeFile/listFiles` 保持抛错不变(降级在 Dart 层做,不动桥语义)。
2. `flutter/lib/platform/platform_workspace.dart`
   - `PlatformWorkspace` 新增 `Future<bool> isAuthorized()`(走新 channel,异常一律按 false 处理)。
   - `createWorkspace()` 改为异步 `Future<Workspace> resolveWorkspace()`:
     - 非 Android → 现有 `fallbackWorkspace`(不变);
     - Android 且 `isAuthorized()` → `PlatformWorkspace()`;
     - Android 未授权 → **`MemoryWorkspace()`**(复用 1.0 的内存实现,含 seed 演示文件 `lib/login.dart`,供演示补丁有目标可改)。
   - 保留旧 `createWorkspace()` 名字做同步兼容包装,避免一次改所有调用点。
3. `flutter/lib/state/chat_session.dart`
   - `workspaceProvider` 改为 `FutureProvider<Workspace>`,内部走 `resolveWorkspace()`;新增 `workspaceDemoProvider = StateProvider<bool>`(true = 当前在内存沙箱)。
   - `_TaskRunner.run()` 里 `_workspaceManager.workspace` 的取用点同步改为等待 resolved workspace(`WorkspaceManager` 增加可选注入,构造时接受外部 workspace,默认行为不变)。
4. `flutter/lib/state/workspace_manager.dart`(如无此文件则在 chat_session 内)——`detectProject()` 在内存沙箱下返回演示项目 `Project(name: 'demo', kind: flutterLike)`,保证演示补丁场景成立。
5. `flutter/lib/features/chat/chat_page.dart`
   - `_DemoBanner` 升级为两条行动线:①「选择工作区目录」(调 `pickDirectory` → 成功后 `ref.invalidate(workspaceProvider)` + 关沙箱提示);②未选择时文案明确「演示沙箱:文件改动不会落盘」。
   - 错误呈现:`ErrorEntry` 渲染前先过 **错误文案映射表**(见 PHASE 28 表),不再出现裸 `PlatformException(...)`。
6. `flutter/lib/features/capabilities/capabilities_page.dart`
   - 插件安装前检查 `workspaceDemoProvider`:沙箱态在安装按钮下提示「插件将装入演示沙箱,授权工作区后需重装」;安装成功文案不变。
7. `flutter/lib/features/profile/profile_page.dart`
   - 工作区 ListTile:未授权时 subtitle 直接给「未选择目录 → 点此选择」,选择后 invalidate 依赖 providers。

### 2.3 页面交互逻辑(正常产品逻辑)
- 首次安装启动 → 对话页出现演示横幅(可关闭)→ 用户直接发消息即可完整体验工具/审批流(沙箱内);
- 用户想真实使用 → 横幅或「我的 → 工作区」选目录 → 全 App 工作区无缝切到 SAF,横幅消失;
- 每次进入对话页若处于沙箱态且未再提示过,横幅只提示一次(SharedPreferences 记 `shelly.demo.banner.dismissed`)。

### 2.4 测试与验收
- 单元:`resolveWorkspace()` 三分支(fake platform channel);MemoryWorkspace 下 demo 补丁任务全链路(复用 closed_loop 测试基建)。
- Widget:未授权态启动 → 演示横幅可见;选目录按钮触发 channel mock。
- 验收:真机全新安装,不选目录,发「演示补丁」→ 审批页弹出 → 批准 → 成功回复;能力页安装示例插件成功。

## 三、PHASE 24:多会话管理(P0)

### 3.1 目标
对话页内完成「新建 / 切换 / 重命名 / 删除」,历史页保留为全量管理入口;与主流 Agent(App 会话抽屉)逻辑一致。

### 3.2 改动清单

1. `flutter/lib/state/settings_store.dart`
   - `ConversationSummary` 增加可选字段 `String? modelId`(PHASE 25 会用)与 `bool pinned`(默认 false,fromJson 容错缺省);`toJson` 同步。
   - 新增 `Future<void> deleteConversation(String id)`(删 summary + 删 `shelly.checkpoint.<id>` + 删标题持久化项)、`Future<void> renameConversation(String id, String title)`。
2. `flutter/lib/state/chat_session.dart`
   - `newConversation()` 增强:若 `state.isBusy` → 先 `cancel()` 并等待 phase 回 idle 再清空(或返回 false 由 UI 提示「任务进行中」——采用后者,语义更清晰);清空后立即 `store.saveConversations` 不动(会话在首次 send 时才落 summary,维持现状)。
   - 新增 `Future<bool> switchTo(String conversationId)`:busy 拒绝;内部复用 `resume()`;成功后 `tabIndexProvider` 不动(由调用方控制)。
   - 新增 `Future<void> deleteCurrentConversation()`:清 entries + `store.deleteConversation`。
   - `_persistConversation()` 已有:确认 title 取首条用户消息前 24 字,更新已有 summary 而非追加重复。
3. `flutter/lib/features/chat/chat_page.dart`(对话页)
   - AppBar 改造:左侧标题区显示当前会话标题(无会话时「新对话」),点击弹 **会话切换 bottom sheet**:
     - 列表 = `store.loadConversations()` 最近 20 条(置顶优先,时间倒序),当前会话高亮打勾;
     - 每行:标题、消息数、相对时间、行尾 ⋯ 菜单(重命名 →对话框;删除 →确认框;删除当前会话后自动进新对话);
     - 顶部「+ 新会话」按钮 = 调 newConversation(busy 时 SnackBar 提示)。
   - 保留现有右上角新建图标,行为与 sheet 内「+ 新会话」一致。
4. `flutter/lib/features/history/history_page.dart`(历史页)
   - `_ConversationTile` 增加长按菜单:置顶 / 重命名 / 删除(删除当前正在进行的会话时先拒绝并提示)。
   - 列表排序:置顶 > updatedAt 倒序。

### 3.3 页面交互逻辑
- 发送第一条消息时会话才诞生并进入列表(避免空会话垃圾);
- 切换会话 = 加载该会话 checkpoint 重建对话流(含工具卡,1.0 已有此能力);
- 删除不可恢复,弹确认框写明「将删除该会话的消息记录与断点」。

### 3.4 测试与验收
- 单元:deleteConversation 连带清理 checkpoint;rename 持久化;title 截断;busy 时 switchTo/newConversation 返回 false。
- Widget:bottom sheet 列表渲染、当前会话高亮、删除当前会话后回新对话空态。
- 验收:真机连续建 3 个会话、来回切换、删除中间一个,历史页计数一致。

## 五、PHASE 26:记忆扩容与可配置(P1)

### 5.1 目标
默认预算放大 8 倍(2000 → 16000 token),全部参数可配置、可在记忆页手动整理并看到整理报告。

### 5.2 改动清单

1. `flutter/lib/core/hermes/forgetting.dart`
   - `ForgettingPolicy` 默认值改为 `maxLedgerTokens: 16000, activeDays: 14, coolingDays: 90, frequencyFloor: 3`(**代码默认值提高**;参数对象本身不变)。
2. 新增 `flutter/lib/core/hermes/memory_settings.dart`
   - `MemorySettings{maxLedgerTokens=16000, activeDays=14, coolingDays=90, frequencyFloor=3, maxAutoEntries=300, recallEntries=8, recallTokens=1200}` + toJson/fromJson + clamp 合法区间(tokens 500~200000,天数 1~365)。
3. `flutter/lib/state/settings_store.dart`
   - `loadMemorySettings()/saveMemorySettings()`(key `shelly.memory.settings`,损坏回默认)。
4. `flutter/lib/state/chat_session.dart`(`_TaskRunner.run`)
   - `HermesMemory(store: ..., autoCapture: ...)` 构造处接入 `store.loadMemorySettings()`:`maxAutoEntries`;`HermesMemory` 增加 `forgettingPolicy`/`reflector` 已有参数,直接传 `ForgettingPolicy(maxLedgerTokens: s.maxLedgerTokens, ...)`;`HermesKnowledgeStore` 传 `maxRecallEntries/recallTokens`。
5. `flutter/lib/state/hermes_provider.dart`
   - snapshot 增加当前 `MemorySettings` 与「整理报告」缓存;新增 `Future<UpkeepReport> runUpkeep()`(手动整理:`const Reflector().reflect(store, force: true)` + `store.applyForgetting(policy)`,返回吸收/清理条数与原因)。
6. `flutter/lib/features/memory/memory_page.dart`(记忆页)
   - AppBar 加设置图标 → **记忆参数页**(`memory_settings_page.dart`):每参数一个带说明的滑块/步进器(token 预算、活跃天数、冷却天数、频次保护、自动条目上限、召回条数/预算),底部「保存」;
   - AppBar 加「立即整理」按钮:执行 runUpkeep → 结果卡「归并 n 条重复 · 清理 m 条(原因分布)」;进行中转圈;
   - 状态卡增加预算进度条:`totalTokens / maxLedgerTokens`,>80% 变警告色。

### 5.3 页面交互逻辑
- 记忆页定位是「可解释 + 可控」:查看 → 调参 → 手动整理,闭环;
- 参数改动**即时生效于下一次** upkeep(自动或手动),不改历史数据;
- 召回预算(recallTokens)是单次注入上下文的量,和账本总量分开解释,页面上分组展示「存储预算」vs「召回预算」。

### 5.4 测试与验收
- 单元:MemorySettings 序列化/clamp;新默认值下 forget 行为(>16000 才裁);runUpkeep 报告计数(复用 closed_loop 的造数法)。
- Widget:设置页滑块保存后重读一致;整理按钮出现报告卡。
- 验收:真机造 200 条记忆 → 整理 → 记忆页计数下降且原因可读;预算条反映 16000。

## 六、PHASE 27:Agent 档案去上限 + 自定义档案(P1)

### 6.1 目标
轮数/工具次数支持「不限制」;档案支持用户自建、编辑、删除;预算触顶时给出可操作的提示而不是一句死话。

   - `AgentLimits` 文档语义扩展:`maxRounds <= 0` / `maxToolCalls <= 0` = 不限制(maxTokens 保留为硬约束,注释写明它是成本保险,不支持关闭)。

   - L277:`while (limits.maxRounds <= 0 || round < limits.maxRounds)`;
   - L333 工具帽:`if (limits.maxToolCalls > 0 && toolCallCount > limits.maxToolCalls)`;
   - `AgentStopped('round_budget_exceeded' / 'tool_budget_exceeded')` 的 message 附带「当前上限 X,可在『我的 → Agent 档案』调整」。
3. `flutter/lib/core/agent_profile.dart`
   - 预设重定义:`平衡助手 32 轮/64 工具`、`谨慎工程师 48 轮/96 工具`、`轻量执行 8/16`、新增 `无限制 0/0(autoCapture true)`;
   - `AgentProfile.copyWith` 已有;补 `isValid`(name 非空,maxRounds/maxToolCalls ≥ 0)。
4. `flutter/lib/state/settings_store.dart`
   - profiles 持久化已有;确认 decode 对新增预设 id 的兼容(老数据里的 id 不在预设表 → 原样保留,不强制迁移)。
5. `flutter/lib/features/profile/profile_page.dart`
   - 档案区尾部加「+ 自定义档案」→ **档案编辑页**(`profile_edit_page.dart`):名称、系统提示词(多行,占位示例)、轮数步进器(0 显示「∞ 不限制」)、工具次数步进器、经验采集开关;保存 = `store.saveProfiles([...原, 新])` 并设为 active;
   - 每张自定义档案卡:可点选激活、长按菜单(编辑/删除;删除内置预设不允许)。
6. `flutter/lib/features/chat/chat_page.dart`
   - ErrorEntry 对 `round_budget_exceeded` 的渲染:文案 + 「去调整档案」按钮跳我的页。

### 6.3 页面交互逻辑
- 「不限制」仍受 token 预算与取消按钮保护(用户随时可停),UI 上在档案卡注明「无轮数上限 · 仍受上下文成本约束」;
- 激活档案只影响**新任务**,进行中任务不变(与模型切换同语义,文档化)。

### 6.4 测试与验收
- 单元:unlimited 轮循环(fake model 连续 30 轮不截断,直到模型自然结束);工具帽 0 = 不限;旧 profiles JSON 兼容;isValid 拒绝空名。
- Widget:编辑页 CRUD 全流程;「∞」显示;错误卡跳转按钮。
- 验收:真机选「无限制」档案跑长任务不出现 round_budget_exceeded;轻量档案 8 轮触顶出现新引导文案。

## 七、PHASE 28:错误文案映射 + 2.1.0 发布(P1)

### 7.1 错误文案映射表(全局唯一出处 `lib/core/error_messages.dart` 新建)

| 原始错误 | 用户文案 | 建议动作 |
|---|---|---|
| `PlatformException(workspace, no workspace directory picked)` | 尚未选择工作区目录 | 去我的页选择目录 / 继续用演示沙箱 |
| `GatewayException(..., status: 401)` | 模型密钥无效 | 我的页检查 API 密钥 |
| `GatewayException(..., status: 404)` | 接口地址不正确 | 检查 Base URL(通常以 /v1 结尾) |
| `GatewayException(..., status: 429)` | 模型限流中 | 稍后重试或更换模型 |
| `TimeoutException` | 网络超时 | 检查网络或本机服务(Ollama 需 App 在同一局域网) |
| `SocketException` | 无法连接服务 | 同上 |
| `round/tool_budget_exceeded` | 已达档案预算上限 | 调高或改用无限制档案 |
| checkpoint `FormatException(version)` | 会话数据版本过旧 | 该会话无法恢复,可删除 |

接入点:`chat_session._brief()`、`ErrorEntry` 渲染、能力页 `_note`、审批失败文案。
