# Shelly Hermes 3.0.0 发布说明

3.0.0 是一次架构升级版本:内部按 v3 迁移计划重构了 Agent 的「思考—能力—审批—任务」链路,对外的聊天、任务、能力、记忆等页面操作习惯保持不变。升级是安全的——首次启动会自动完成数据迁移,旧数据全部保留,出问题会自动回滚(见下文「升级与数据安全」)。

## 这次更新带来了什么

### 1. 任务开工前先「预检」(Brain)

以前接到一个任务就直接开跑;现在模型会先做一轮轻量的意图识别与计划预检,把「这个任务大概分几步、要用什么能力」想清楚再动手。好处:

- 复杂任务的步骤更连贯,减少一开始就跑偏的情况;
- 预检消耗算力很少,且与任务执行共用同一个额度账本,不会产生看不见的额外开销;
- 预检默认开启;如果预检本身出错,任务仍按原有方式执行,不会被卡住。

### 2. 技能可以被模型自己发现和使用了

已注册的技能(内置技能、DSH 插件技能)现在会出现在模型的工具面上:模型可以列出当前有哪些技能可用,并在合适的时候主动调用。同时模型只会「看到」当前环境里真实可用的能力(文件、终端、MCP 服务器、桥接等),不会再对不存在的工具抱有幻想。DSH 插件与 MCP 服务器在底层统一挂接为同一种「能力」,并带有信任评分,管理起来更一致。

### 3. 新增「使命」页:任务的完整时间线

底部导航新增第 6 个「使命」Tab。这里以只读方式展示任务的完整时间线——每个任务从创建到结束经历了什么、每一步发生了哪个事件,都可以点开查看详情。它不改变你创建和管理任务的方式,只是让「刚才 agent 到底做了什么」变得可回溯。

### 4. 审批链路更稳

需要你批准/拒绝的操作(如文件写入)走的是一条解耦后的审批通道。界面上审批弹窗、Diff 展示、批准/拒绝的操作都和以前一样,但这条链路现在与核心引擎隔离,后续扩展审批策略(例如更细粒度的权限)不再需要动引擎本体。

### 5. 升级安全网(本次升级最核心的保障)

3.0 引入了一套五段式迁移流程:备份 → 校验 → 迁移 → 复核 → 回滚,全部在升级后首次启动时自动完成,无需任何手动操作(详见下节)。

## 升级与数据安全

从 2.2 / 2.3 / 2.4 版本升级到 3.0.0 时:

1. **自动迁移,无需手动操作。** 首次启动新版本时,后台自动完成数据迁移,通常在几秒内结束,之后正常进入应用。
2. **旧数据全部保留。** 迁移只做「形状转换 + 写入新键」,旧的会话、记忆、日程、设置等数据一律保留不删,作为回滚锚点。
3. **先备份,后动手。** 迁移开始前,所有受影响的配置键会先完整备份一份。
4. **自动复核,失败自动回滚。** 迁移完成后系统会回读关键数据的计数与摘要,与备份记录逐项比对;任何一项不一致,都会自动用备份恢复数据,并标记回滚状态。回滚完成后,你的数据与升级前逐字节一致——即使 3.0 的迁移出了问题,你退回旧版本时看到的数据和升级前一模一样。
5. **绝不因迁移卡死。** 整个迁移带有 8 秒超时保护;即使迁移环节出现异常,应用也会照常启动(失败开放策略),并把详细原因写入崩溃日志便于排查,你的数据仍受备份保护。

## 回滚建议

如果你想从 3.0.0 退回 2.x:直接安装旧版本 APK 即可。因为迁移从不删除旧键,旧版本读到的仍是升级前的原始数据。若 3.0 已触发自动回滚(`shelly.migration.state=rolledback`),数据同样保持与升级前逐字节一致,可放心降级。
